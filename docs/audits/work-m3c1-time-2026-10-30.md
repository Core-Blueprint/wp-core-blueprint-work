# M3-C1 — Manager Time controls and own recent entries inside Work

Date: 2026-10-30

Parent: `5a4a4ca327fe34a6a4144714817f4322a351384b`
Classification: **SOURCE BATCH, canonical Level 1/2/3 and FIELD HOLD**

## Design decision

Time already has stable production-grade `Time\Access`, `Repository\Timers`, `Repository\TimeEntries`, `Time\WorkItemPickerSearch`, a global Timer HUD, and native Time pages for Timer, Manual Entry and Time Entries. Existing Time CAS, DST/precision and zero-duration policies are protected Golden. A parallel time database or SPA state store would be incorrect.

M3-C1 implements **manager in-place Time access** across all Work views. It is a cohesive first part of Time integration; more complex manual creation, correction, bulk and tracker-only Time parity remain M3-C2. Existing Time WordPress menus/routes remain authorized and accessible via a real **Open Time workspace** link; tracker-only users retain their separate Time landing.

## Implementation

- `Transport\Rest\WorkspaceTimeController`: strict, server-authorized GET `cb-work/v1/workspace/time` for **current actor's** active timer and **10** completed Time Entries per page with canonical SQL paging, GET `/workspace/time/work-items` via actor-aware bounded `WorkItemPickerSearch::results`, and POST `/workspace/time/timer` with explicit `start` or `stop`. Only a manager currently inside Work may use this new route. Every callback rechecks manager capability, authenticated actor, Base/Work runtime and current schema. Time-only roles continue using native, broader Time controls; no unauthenticated read route exists.
- Timer mutations delegate to the **existing `Timers::start` / `Timers::stop`** transactional repositories. Start validates `Time\Access::can_track_work_item` with the current actor. Stop exclusively targets the current actor, uses `Time\Access::can_stop_user_timer`, and ignores any client-supplied user identifier. Successful actions preserve the same governance audit events `TIMER_STARTED` / `TIMER_STOPPED` as native handlers. Errors return guarded REST responses, not false success. No parallel scheduler or timer persistence.
- The GET read projects only safe names, UTC timestamps, duration, source and revision for **the actor's own entries**. SQL queries are actor-filtered and bounded; the callback repeats each entry's actor ownership and `Access::can_view_entry`. Entry notes and confidential metadata are excluded. The own timer includes own note, start and Work Item label.
- `Admin\WorkspaceTimePanel`: hidden-by-default progressive-enhancement Time panel in the shared Work shell, activated from the existing Time operations link. It includes Work Item search/selection, note, Start/Stop, active timer status, recent entries and paging, and a real native Time fallback. The `Work` screen retains Overview + Work as only manager menu entries.
- `assets/js/workspace/time.js`: safe text-only DOM, separate read and picker cancellation epochs, same-origin WordPress REST nonce, bounded and typed response validation, no untrusted HTML, safe 403/invalid response concealment, disabled controls during mutation and no full-page reload. A successful timer mutation emits `cb-work-time:changed`, which the existing **global Time HUD** now listens for and re-reads through its existing canonical Ajax endpoint, avoiding two independent client timer stores. It also refreshes the M3-A Operations summary.
- `tools/prepare-workspace-modules.py` includes `time.js` in the deterministic content-addressed staged ESM graph. `src/Admin/Assets.php` fails closed on a missing module. Work-scoped CSS remains responsive, accessible and explicitly keeps the `hidden` state authoritative for Time form and pagination. Reuses existing translation catalog strings; no POT/PO changes, no Base edits.
