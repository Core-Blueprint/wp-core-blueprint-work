# M3-UX3-F2E | Viewport-aware Kanban Scrolling

Date: 31 October 2026
Base source: `6443d70f3b0425d31f0957c6969bc2af4bcd4aba`
Owner GO: make horizontal scrollbar reachable without scrolling down large Kanban columns and retain responsive/keyboard/DnD behavior.

## Root cause and boundaries

`assets/work-admin.css` uses CSS Grid for four 280px-min lanes with `overflow-x: auto` but no vertical size limit. The scrollbar therefore appears below the *tallest* lane. Existing Base `assets/js/core/reorder.js` autoscrolls `window` near vertical edges, but not independent lists or the horizontal board. Preserved native page and protected `src/Admin/WorkItemBoardRenderer.php`; only Workspace's imported canonical Board opts into the new behavior.

## Design

One native horizontal scroll surface, `.cb-work-items-kanban`; no duplicated or synchronized scrollbar. A bounded `board-viewport.js` module measures real board top against `visualViewport.height/innerHeight` and sets only `--cb-work-board-available-block`. Work scoped CSS gives Board and lanes a calculated max height. Each reorder-list is independently scrollable, header/footer remain visible. Short and empty lanes preserve natural height via `align-items: start` rather than stretching to the tallest lane. The lane height subtracts the native Base top/bottom padding so the footer is not clipped. Native scrollbar stays near viewport bottom for long lanes. A synthetic Chromium (Playwright) layout fixture verified: 630px Board, 610px long lane, 180px short lane, 118px empty lane, independently scrollable long list and `board.scrollHeight===board.clientHeight` without vertical clipping. This is **not** a real WordPress FIELD test. `ResizeObserver` watches context row and toolbar; window and visual viewport resize/scroll update a single scheduled measurement. No fixed WP admin bar height. CSS/workspace tokens remain Base-aligned. Pointer edge scrolling assists Base's existing reorder on active drags without taking over validation/commit; Shift-wheel and empty-gap mouse panning are optional enhancements. No new scrollbar visuals or duplicate state engine.

Lifecycle: initialize only after canonical Board import + official mount, rehydrate Board positions on same-view refresh, destroy listeners/observers on view replacement, fallback, 401/403 and abort. ESM `board-viewport.js` added to immutable workspace packager's `REQUIRED` graph and joined through `canonical-mount.js`. Native Work Items/Calendar unaffected.
